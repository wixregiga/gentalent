# round-one: behavior inventory of the Python bot

Purpose: every behavior the Python bot has at commit 386d9fa, so a Go test can be written for
each before the Python is replaced (Q33, Q27 item 5, decision D2). Line numbers refer to that
commit.

How to read an entry: behavior, then `Src:` (the code), then `Test:` (the Python test that
covers it, or `none`), then a tag.

- `KEEP`: round one leaves it as is. The Go port must reproduce it.
- `CHANGES`: a round-one rule or decision changes it (Q number, R number or domain key named).
- `QUESTION`: unclear whether round one changes it; the reason follows.

Placeholders in quoted reply text: `{member}` the acting Member's roster `name`, `{nominator}`
the case nominator's roster name, `{target}` a shamed Member's roster name, `{nominee}` the
stored display name, `{n}` a vote count, `{cmd}` `!gt` or `!!gt`. `\n` is a newline and `  \n` is
two spaces plus a newline (a Markdown hard break). Every text reply is sent with the prefix
`@gentalent-bot says: ` in front of the quoted text (B140). Names in examples are fictional;
where a literal in the code names a real person, the entry says `<example name>`.

One test name contains a real person's name; it is cited by glob as
`tests/test_workflow.py:WorkflowTest.test_*_scenario_and_final_command` (the only match).
